## 安装

1. 安装 Tampermonkey 或兼容的用户脚本管理器。
2. 打开 `pigai-typing-simulator.user.js`，复制全部内容。
3. 在 Tampermonkey 中新建脚本，删除编辑器中的默认内容，粘贴完整脚本并保存。
4. 打开或刷新批改网作文页面：

   ```text
   https://www.pigai.org/index.php?c=...
   ```

5. 页面右下角出现“批改网模拟打字”面板后即可使用。

## AI 配置

脚本使用 OpenAI Chat Completions 兼容格式。以硅基流动为例：

```text
API Base URL: https://api.siliconflow.cn/v1
模型:         deepseek-ai/DeepSeek-V4-Flash
API Key:      填写你自己的 API Key
```

也可以使用其他兼容服务商，只需填写其 Base URL、模型名称和 API Key。配置会保存在当前浏览器的 `localStorage` 中，不会写入脚本文件。

## 使用流程

1. 确认页面存在作文要求区域 `#request_y` 和作文框 `textarea#contents`。
2. 填写 API Base URL、模型和 API Key。
3. 点击“AI生成作文”。脚本会读取页面题目和词数要求，并将生成的英文作文直接填入插件文本框。
4. 脚本会从题干中提取标题并填入页面的 `input#title`（见下节“标题自动填写”）。
5. 检查作文内容、词数和页面标题。
6. 设置基础打字速度，点击“开始”。脚本会逐字符输入，并触发常见输入事件。点击“开始”时同样会先尝试填写标题。

## 控件说明

- **AI生成作文**：调用配置的接口生成作文并自动填入插件文本框。
- **读取剪贴板**：浏览器拦截普通粘贴时，从系统剪贴板读取作文文本。
- **开始**：将插件文本框内容逐字符写入批改网作文框。
- **暂停/继续**：暂停或恢复当前输入任务。
- **停止**：终止当前输入任务，已输入内容会保留。
- **打字时抢占焦点**：默认关闭。关闭时脚本不要求作文框处于聚焦状态，打字期间可以照常操作面板或页面其他区域；开启后会在开始输入时把焦点移到作文框。
- **自动填写页面标题**：根据作文要求自动设置 `#title`，关闭后保留现有标题。

## 标题自动填写

点击“AI生成作文”或“开始”时，脚本都会从 `#request_y` 的题干里提取标题并写入页面标题框（可用面板中的“自动填写页面标题”开关关闭）。写入时会派发 `input` 和 `change` 事件，并**不改动焦点**，以免打断紧随其后的作文输入。

按“明确字段 → 常见句式 → 兜底”的顺序匹配，支持的常见写法：

| 题干写法 | 提取结果 |
| --- | --- |
| `Write an essay about "My Campus Life"` | `My Campus Life` |
| `Title: "My Campus Life". Write at least 120 words.` | `My Campus Life` |
| `Please write an essay entitled "My First Job".` | `My First Job` |
| `You should write an essay titled "City Life vs Country Life".` | `City Life vs Country Life` |
| `Your title: A Memorable Trip. 120 words.` | `A Memorable Trip` |
| `题目："我的大学生活"，不少于 120 词。` | `我的大学生活` |
| `作文题目：《我的家乡》` | `我的家乡` |
| 题干里只有一处短引号短语 | 该短语（兜底） |

写入位置优先使用 `input#title`；页面改版导致该元素不存在时，会在题目所在表单内依次尝试 `input[name="title"]`、`input#essay_title`、`input.title`。

### 批改网真实题干（无引号）

批改网内页（`c=v2&a=write`）的题干通常**不带引号**，标题直接写在“要求”段落里，例如作文 3435109：

```text
要求
写作2-Reflections on My Choice of Major
作文号:3435109   教师:张丽娜   字数:100~200   满分:100
```

此时标题就在 `写作N-` 之后。脚本按行处理题干，因此**无论 `#request_y` 只包住要求段落、还是连 `作文号/教师/字数/满分` 一起包住**，都能提取出 `Reflections on My Choice of Major`，并且不会把 `作文号`、`字数` 等元信息当成标题。页面顶部的 `题目：[3435109]25级…-写作2-…` 形式同样支持。

如果题干里确实没有标题，脚本不会乱填，并会给出提示：已识别题目但未提取到标题；如果提取到了标题却找不到标题框，则提示未找到 `#title`。这两条提示方便区分是题干问题还是选择器失效。

**注意**：批改网的标题框默认会被预填成 `第<作文号>号 作文`。脚本会自动覆盖为提取到的标题；如果该输入框在页面上是只读的，脚本会保持原值并在面板提示。

## 打字节奏

基础速度单位为字符/分钟。每个字符的间隔在基础值上下约 10% 波动；空格和标点会增加小幅停顿。速度不是固定延迟，页面卡顿或浏览器后台节流也可能影响实际节奏。

## 常见问题

### 点击 AI 生成后报错

- 检查 API Key 是否有效、账户是否有余额或调用额度。
- 检查 Base URL 是否包含正确的 `/v1` 路径。
- 检查模型名称是否仍在服务商的可用模型列表中。
- 打开浏览器开发者工具查看接口返回的 HTTP 状态和错误信息。

### 找不到作文框或标题框

刷新页面并等待题目区域加载完成。脚本默认查找：

```css
#request_y
textarea#contents
input#title
```

如果网站改版导致选择器变化，需要同步调整脚本中的选择器。

### 无法粘贴

请先整体替换为最新脚本并刷新页面。插件面板内的作文框、API Base URL、模型和 API Key 输入框都已单独处理粘贴事件；仍失败时使用“读取剪贴板”按钮。

### AI 生成词数不准确

模型输出可能偏离限制。生成后请检查英文单词数，并在插件文本框中手动修改后再开始输入。

## 输入行为

脚本通过修改作文框的值并派发 `input` 事件来写入内容，插入位置在改动前自行计算，**不依赖作文框是否处于聚焦状态**，也不再模拟键盘事件。因此：

- 打字过程中可以自由点击面板按钮或页面其他位置，输入不会中断。
- 如果作文框在打字期间失焦，后续字符会追加到末尾，不会因为页面重置输入位置而错位。
- 需要在输入时自动把光标移入作文框，可勾选面板中的“打字时抢占焦点”。

## 后台标签页

把批改网标签页切到后台后，脚本仍会继续输入，不会停在原地。原因是浏览器会节流后台页面的 `setTimeout`（短延时先被抬到约 1 秒，长时间隐藏后进一步降到约每分钟一次），所以脚本不再用定时器驱动打字节奏：

- **前台**：使用原生 `setTimeout` 精确计时，不产生额外开销。
- **后台**：改用 `MessageChannel` 的消息事件自查是否已经等够，节拍由 `requestAnimationFrame` 控制。这两者都不依赖 `setTimeout`，因此不会被节流到停住。
- 等待时长始终按真实经过时间计算，所以即使被节流，节奏也不会失控。

后台的推进速度取决于浏览器给该页面分配的任务节拍。实测在帧率被压到约 1 次/秒时，输入速度也相应降到约 1 字符/秒（而不是停止）；`requestAnimationFrame` 可用时不会出现高频空转，每次节拍只做一次检查。
